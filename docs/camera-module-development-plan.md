# 相机模块增强开发文档

> 文档状态：Draft  
> 适用范围：`apps/mobile/lib/features/camera`  
> 开发原则：本地优先、真机优先、能力检测、渐进降级

## 1. 目标

相机模块的目标不是复制系统相机，而是提高普通用户拍出可用照片的成功率：在拍摄前提供易理解的构图与稳定性指导，在拍摄后自动选出质量更好的照片，并与本地编辑、AI 创作和作品库形成闭环。

核心指标：

- 首次拍摄完成率。
- 重拍次数。
- 连拍最佳照片采用率。
- 拍摄结果进入编辑或 AI 创作的比例。
- 相机崩溃率和初始化失败率。
- 单次拍摄峰值内存与处理耗时。

## 2. 当前能力基线

当前已经具备：

- 前后摄像头、闪光灯、缩放、比例和相册导入。
- 多物理镜头识别与切换。
- 点击对焦、曝光补偿、焦点锁定和硬件快门入口。
- 三分、中心、对称、引导线、框中框和黄金分割构图线。
- 水平仪、实时构图提示、人体姿态与场景分析入口。
- 亮度/RGB 直方图、高光和暗部裁切分析。
- 峰值对焦、镜头清洁提示和实时画面清晰度分析。
- 定时拍摄、五连拍、长按连续拍摄和智能快门。
- 多帧 HDR、夜景降噪、照片风格和自拍镜像。
- 按设备内存自适应 720p/1080p 拍照分辨率，诊断面板显示当前档位。
- iOS 原生 ISO、快门、白平衡和对焦手动参数（自动/半自动/全手动）；
  Android 受 CameraX 插件限制，能力面板会明确提示暂不支持手动曝光。
- 连拍照片的清晰度、曝光、对比度及裁切损失评分。
- 感知哈希去重、最佳照片排序、质量标签和自动保存。
- 本地作品库保存、相册保存和后续编辑/AI 创作入口。

## 3. 产品边界

### 3.1 首期增强范围

- 人像智能选片。
- 拍摄稳定性与手抖评分。
- AE/AF 分离和锁定交互。
- 人像构图指导。
- 斑马纹曝光警告。
- 场景拍摄预设。
- 设备能力与故障诊断。

### 3.2 后续范围

- ISO、快门、白平衡和手动焦距。
- RAW/DNG 与 RAW+JPEG。
- 动态照片、全景、延时和长曝光。
- 视频拍摄与视频稳定。
- 文档多页扫描及 PDF 导出。

上述能力依赖 Camera2 或 AVFoundation 时，必须通过平台通道和能力检测实现，不得假设所有设备支持。

## 4. 目标架构

```text
CameraPage
├── CameraLifecycleController     初始化、前后台切换、错误恢复
├── CameraControlController       镜头、闪光、缩放、AE/AF、专业参数
├── CameraAnalysisPipeline        帧采样、节流和分析调度
│   ├── ExposureAnalyzer          直方图、斑马纹、明暗裁切
│   ├── StabilityAnalyzer         手抖、水平与稳定窗口
│   ├── PersonAnalyzer            人脸、眼睛、笑容、人体关键点
│   └── SceneAnalyzer             场景和拍摄建议
├── CaptureCoordinator            定时、单拍、连拍、智能快门
├── PhotoQualityEvaluator         质量评分、去重、最佳照片排序
├── CapturePresetRepository       本地场景预设
└── CameraSessionController       本次拍摄及选片状态
```

当前 `camera_page.dart` 体积较大，增强过程中应逐步拆分职责；不得一次性重写整个相机页面。

### 4.1 分析管线约束

- 实时分析不阻塞预览和快门。
- 同一时间最多执行一个重型视觉分析任务。
- 根据设备性能将分析频率限制在每秒 2～8 帧。
- 页面不可见、进入预览或 App 进入后台时立即停止图像流。
- 单个分析器失败只关闭对应能力，不终止相机。
- 所有分析结果携带时间戳；UI 不展示过期结果。

## 5. 分阶段开发序列

### C1：稳定性参与拍摄与选片

交付：

- 从加速度计数据计算稳定性分数和稳定持续时间。
- 快门触发时记录本次运动强度。
- 将手抖惩罚加入连拍质量评分。
- 智能快门仅在画面连续稳定一段时间后触发。
- 夜景与 HDR 使用更严格的稳定阈值。
- 显示“请保持稳定”“可以拍摄”等非阻塞提示。

验收：

- 静止设备不会被误判为持续晃动。
- 明显移动时智能快门不会触发。
- 相同画质下，晃动较少的帧排序更高。
- 传感器不可用时自动退化为不含稳定分的评分。

### C2：人像智能选片

交付：

- 人脸检测开启轮廓、眼睛和笑容分类。
- 为每张候选照片计算人脸数量、主体人脸清晰度、睁眼概率、笑容概率和遮挡风险。
- 多人合照支持“全员睁眼”评分。
- 人像指标与通用画质指标合并，但无人物照片不扣分。
- 预览页解释推荐原因，如“人物清晰、全员睁眼”。

建议评分：

```text
通用照片：
总分 = 清晰度 48% + 曝光 30% + 对比度 22% - 裁切损失

人物照片：
总分 = 通用画质 55%
     + 人脸清晰度 20%
     + 睁眼状态 15%
     + 表情与遮挡 10%
```

验收：闭眼照片不会被推荐为最佳；多人照片中全员睁眼的候选优先；检测失败时仍可使用通用评分完成选片。

### C3：AE/AF 分离与锁定

交付：

- 单击设置 AF 点。
- 从焦点环拖出独立 AE 测光点。
- 长按锁定 AE/AF，再次点击或切换镜头解除。
- 显示 AF、AE、AE/AF Lock 三种清晰状态。
- 拖动曝光滑杆不会隐式改变焦点。
- 切换镜头、App 后台恢复和拍摄异常后恢复自动模式。

验收：支持设备上焦点与测光点可以独立移动；不支持设备只保留曝光补偿并给出轻量提示；锁定状态和实际相机状态一致。

### C4：人像构图指导

交付：

- 依据人脸框和人体关键点识别半身、全身及多人场景。
- 检测头顶留白、视线方向留白和主体偏移。
- 提示避免眼睛、手腕、膝盖和脚踝贴边或卡边。
- 多人场景评估站位间距和画面平衡。
- 提示具备冷却时间，相同提示不会持续闪烁。

验收：提示不遮挡快门和主体；用户关闭实时指导后停止相关分析；低置信度结果不展示确定性文案。

### C5：斑马纹与专业曝光辅助

交付：

- 在实时亮度采样结果上生成高光斑马纹遮罩。
- 提供 90%、95%、98% 三档高光阈值。
- 可选显示严重暗部警告。
- 斑马纹、直方图和裁切百分比使用同一份亮度分析结果。
- 低性能设备自动降低遮罩刷新率。

验收：斑马纹位置与高光区域基本一致；关闭后不继续计算遮罩；开启斑马纹不会明显降低预览流畅度。

### C6：场景拍摄预设

内置预设：

| 预设 | 比例 | 构图 | 连拍 | 增强 | 默认风格 |
|---|---:|---|---:|---|---|
| 人像 | 3:4 | 三分 | 5 | 标准 | 柔和 |
| 美食 | 1:1 | 中心 | 1 | HDR | 暖色 |
| 夜景 | 9:16 | 黄金分割 | 1 | 夜景降噪 | 冷色 |
| 宠物 | 3:4 | 中心 | 5 | 标准 | 鲜艳 |
| 探店 | 3:4 | 框中框 | 1 | HDR | 标准 |
| 风景 | 16:9 | 黄金分割 | 1 | HDR | 鲜艳 |

交付：

- 预设本地版本化存储。
- 一键应用比例、构图、连拍、增强和风格。
- 允许复制内置预设并保存为自定义预设。
- 模板进入相机时，模板参数优先于默认预设。

验收：重启 App 后自定义预设仍存在；预设升级不覆盖用户修改；不支持的增强模式自动降级。

### C7：原生专业控制

交付：

- Android Camera2 与 iOS AVFoundation 能力映射。
- ISO、快门时间、白平衡、色温和手动焦距控制。
- 自动、半自动和全手动模式。
- 参数范围严格来自当前物理镜头能力。
- 不支持的参数不展示或明确置灰。

验收：参数值不会超出硬件范围；切换物理镜头后重新加载能力；异常参数不会导致相机会话崩溃。

### C8：诊断与发布质量

交付：

- 相机初始化耗时和失败阶段记录。
- 当前镜头、支持能力、分析帧率和降级状态展示。
- 剩余存储空间、图片处理内存和设备温度预警。
- 可复制的诊断报告，不包含图片、API Key 或精确位置。
- Android/iOS 主流机型真机兼容矩阵。

验收：用户可以从错误页恢复、切换镜头或进入系统权限设置；诊断信息足以定位初始化、权限、存储和插件问题。

## 6. 数据模型建议

```dart
class CaptureContext {
  final String cameraId;
  final String lensType;
  final double zoom;
  final double exposureOffset;
  final double stabilityScore;
  final String? presetId;
  final DateTime capturedAt;
}

class PhotoQualityMetrics {
  final double totalScore;
  final double sharpness;
  final double exposure;
  final double contrast;
  final double clippingPenalty;
  final double stability;
  final PortraitQualityMetrics? portrait;
}

class PortraitQualityMetrics {
  final int faceCount;
  final double faceSharpness;
  final double eyesOpenScore;
  final double smileScore;
  final double occlusionRisk;
}
```

质量指标应与照片一同写入本地作品元数据，使最佳照片推荐可解释、可回归测试。

## 7. 性能预算

- 相机首帧：中端真机目标小于 1.5 秒。
- 普通实时分析：单次小于 80 ms。
- 人脸/姿态分析：平均每秒不超过 5 次。
- UI 刷新：分析结果最多每秒更新 10 次。
- 五张高分辨率连拍：拍摄处理与质量评分共用一次解码，最多两个并发任务。
- 选片过程：五张照片目标 2 秒内完成。
- 后台或预览页：图像流必须停止。

分辨率策略：camera 插件的预览、拍照和图像分析共用一个分辨率设置。
iOS 与内存不低于 5 GB 的 Android 设备使用 1080p，其余设备保持 720p；
清晰度分析采样步长随分辨率缩放，避免升档后实时分析成本翻倍。

分析调度：实时引导关闭时跳过姿态、人脸和场景推理；扫码模式只运行条码
检测，不再为扫码承担姿态/人脸/场景模型的开销。场景标签约 2～4 秒一次，
从关闭切回开启时立即补一次。

生命周期：短暂失去焦点（通知栏、控制中心、来电浮层）只暂停预览与分析，
恢复时沿用相机会话；进入 hidden/paused 才释放相机。页面被其他路由覆盖时
停止图像分析流，返回后自动恢复。图像流连续 4 秒没有新帧时自动重启一次，
失败则降级为无实时分析。

如果连续分析超过预算，依次降低采样尺寸、分析频率，再关闭非核心分析器；不能影响快门可用性。

## 8. 隐私与安全

- 实时相机帧默认只在设备内处理。
- 人脸、姿态和场景分析结果不用于身份识别。
- 不保存人脸特征向量。
- 未经用户提交，不把预览帧发送到第三方 AI 服务。
- 保存和分享时按用户设置移除位置、设备等 EXIF 信息。
- 诊断报告不得包含照片内容、文件路径中的个人信息或密钥。

## 9. 测试矩阵

### 9.1 单元测试

- 稳定性窗口与阈值。
- 曝光、清晰度、对比度和裁切损失评分。
- 人像指标合并规则。
- 感知哈希去重。
- 预设升级与用户覆盖。
- 不支持能力的降级路径。

### 9.2 Widget 测试

- 权限拒绝和永久拒绝页面。
- AE/AF 锁定状态。
- 构图选择面板。
- 质量标签和最佳照片推荐原因。
- 专业参数的隐藏、禁用和边界显示。

### 9.3 真机测试

至少覆盖：

- Android：低端、中端、旗舰各一台。
- iOS：一台较旧设备和一台多镜头设备。
- 前后摄像头、超广角、主摄和长焦。
- 弱光、逆光、室内、人像、多人和运动主体。
- 权限拒绝、来电/切后台、低存储和连续拍摄。

## 10. 完成定义

相机增强阶段完成必须同时满足：

- 无新增能力时，相机基础拍摄仍可独立工作。
- 所有硬件能力都先检测后使用。
- 实时分析不会阻塞快门。
- 最佳照片推荐能够展示主要原因。
- 失败和降级状态有明确但不打扰拍摄的提示。
- 核心算法具备单元测试，关键交互通过真机回归。
- App 进入后台、切换镜头和页面退出时资源正确释放。

## 11. 推荐实施顺序

1. C1 稳定性参与拍摄与选片。
2. C2 人像智能选片。
3. C3 AE/AF 分离与锁定。
4. C5 斑马纹曝光警告。
5. C6 场景拍摄预设。
6. C4 人像构图指导。
7. C7 原生专业控制。
8. C8 诊断与发布质量。

每个阶段单独交付和验收，不等待全部专业能力完成后再发布。
