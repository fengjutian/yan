# 本地 App 优先开发序列

> 目标：优先把 Flutter App 做成无需部署后端也能完成拍摄、编辑、生成、保存和分享的可用产品；云端同步、额度、订阅与运营后台后移。

## 1. 开发原则

1. 默认本地可用：首次启动、拍摄、导入、编辑、作品管理和分享不得依赖 Go、MySQL、Redis 或 MinIO。
2. 数据归用户设备：原图、编辑结果、草稿、收藏和生成记录优先保存在 App 私有目录，并提供删除能力。
3. AI 可插拔：本地直连 AI 与后端代理实现同一接口；未配置 AI 时，本地拍摄和编辑仍可正常使用。
4. 先闭环再扩展：每个阶段都必须形成可演示、可测试、可回归的用户路径。
5. 保留云迁移边界：本地模型使用稳定 ID、时间戳和版本字段，为未来登录后同步预留空间，但当前不阻塞本地功能。

## 2. 本地优先完成定义

用户在不启动任何后端服务时可以完成：

```text
首次启动
→ 浏览灵感模板
→ 拍照或从相册导入
→ 裁剪、旋转和调整画面
→ 可选调用本地配置的 AI 服务生成图片
→ 对比并保存满意版本
→ 在作品、收藏和草稿中继续管理
→ 导出到相册或调起系统分享
```

关闭网络或没有配置 AI Key 时，除 AI 生成外的功能仍应可用，并给出明确状态提示。

## 3. 开发序列

### L0：本地运行基线

交付：

- 固化 Flutter SDK、依赖安装、代码生成、分析和测试命令。
- 建立开发/测试配置，默认进入本地模式。
- 清理启动流程中的后端强依赖和无效路由。
- 增加本地数据目录与缓存目录约定。

验收：全新环境只启动 Flutter App 即可进入首页；`flutter analyze` 和现有测试通过。

### L1：本地作品数据层

交付：

- 用结构化本地数据库替代仅靠 `SharedPreferences` 和零散文件的作品存储。
- 建立作品、素材、编辑版本、草稿、收藏和模板收藏模型。
- 保存原图、缩略图、导出图、创建时间、来源、尺寸和编辑参数。
- 增加数据库迁移、文件一致性检查和孤儿文件清理。

验收：重启 App 后数据完整；升级数据库不丢作品；删除作品时可同时删除其本地衍生文件。

### L2：拍摄与导入闭环

交付：

- 完善拍照、前后摄像头、闪光灯、缩放、比例和相册导入。
- 稳定三分线、中心线、对称线、水平状态和实时提示。
- 拍摄后提供重拍、保存原图、进入编辑和进入 AI 创作。
- 统一相机权限、相册权限、拒绝权限和设备不支持时的降级提示。

验收：Android 与 iOS 真机完成“拍摄/导入 → 预览 → 保存到本地作品库”；权限拒绝不会导致白屏或崩溃。

### L3：本地编辑与版本历史

交付：

- 完成裁剪、旋转、亮度、对比度、饱和度和平台比例预设。
- 增加撤销、重做和重置操作栈。
- 每次显式保存生成一个作品版本，保留原图和编辑参数。
- 支持原图/效果滑动对比，从任意历史版本继续编辑。
- 导出过程统一处理方向、色彩格式和 EXIF 隐私信息。

验收：连续撤销和重做结果正确；退出编辑再进入可恢复草稿；历史版本可以独立预览和导出。

### L4：本地灵感模板

交付：

- 将内置模板从代码常量迁移为版本化本地资源。
- 支持分类、搜索、排序、收藏和离线封面。
- 模板可携带构图、机位、站位、提示词和推荐风格进入相机或工作室。
- 为未来远程模板更新定义导入格式，但暂不依赖 `/templates` 接口。

验收：离线可浏览和收藏全部模板；模板参数能完整传递到拍摄和创作流程。

### L5：本地 AI 配置与生成

交付：

- 统一 `AIClient` 抽象，隔离 MiniMax、兼容接口及未来后端代理。
- 本地安全保存 Base URL、模型名和 API Key，不写日志、不进入作品导出数据。
- 支持文生图、人物参考创作、风格选择、比例和生成中状态。
- 实现超时、取消、有限重试、错误分类和生成失败记录。
- 明确提示本地直连会将图片发送给用户配置的服务商，并记录用户同意状态。

验收：配置有效时可完成生成并写入本地作品库；无 Key、断网、超时和服务错误都有可恢复提示；本地 Key 不以明文出现在日志或普通配置文件中。

### L6：本地作品、收藏与草稿

交付：

- 作品页支持缩略图网格、时间排序、类型筛选和详情查看。
- 收藏和草稿改用本地结构化数据，不再只保存任务 ID。
- 支持重命名、复制版本、批量选择、删除和从草稿继续编辑。
- 增加“删除原图及全部衍生版本”和“清空本地数据”。

验收：作品、收藏、草稿都能离线使用；删除和批量操作具有确认及明确结果；不存在指向已删除文件的记录。

### L7：分享工作台

交付：

- 完成常用平台比例、留白、水印位置、高清保存和系统分享。
- 增加多图排序、封面选择和基础拼图。
- AI 文案为可选能力；未配置 AI 时允许手工编辑标题、正文和标签。
- 导出默认移除位置、设备等 EXIF 信息。

验收：单图和多图均能生成可分享文件；关闭网络仍可编辑文案、导出图片并调起系统分享。

### L8：可靠性、隐私与发布准备

交付：

- 补齐本地仓库、编辑器、生成状态机和数据迁移测试。
- 完成低存储空间、大图、损坏图片、进程中断和重复点击测试。
- 增加隐私说明、AI 同意管理、缓存清理和诊断信息导出。
- 完成 Android/iOS 真机构建、签名、图标、启动页和发布检查表。

验收：核心离线闭环通过自动化测试和真机回归；进程被杀后不会留下无法识别的半成品；发布包不包含测试 Key 或开发地址。

## 4. 后移到云端阶段的功能

以下功能不阻塞本地 App 首版：

- 账号注册、登录和跨设备同步。
- 游客数据迁移到正式账号。
- 云端作品、收藏、草稿和模板收藏。
- 每日额度、会员、套餐、订单和支付。
- 服务端异步队列、失败退款和补偿扫描。
- 运营管理后台、远程模板管理和审核后台。
- 多 Provider 路由、SSE 通知、熔断和成本控制。

## 5. 云端接入顺序

本地闭环稳定后，按以下顺序接入云端：

1. 账号与本地数据迁移。
2. 作品和配置的可选云同步。
3. 后端代理 AI，保留本地直连作为开发或高级选项。
4. 云端模板与版本更新。
5. 每日额度、套餐、订单和后台运营。

云端接入不得破坏离线浏览、编辑、作品管理和本地导出能力。

## 6. 当前实施优先级

从现有代码状态出发，立即执行顺序为：

1. L1 本地作品数据层。
2. L3 编辑版本历史与撤销/重做。
3. L6 收藏、草稿和作品管理结构化。
4. L4 模板资源化。
5. L7 多图分享。
6. L2、L5 的真机稳定性与错误恢复补强。
7. L8 发布准备。

现有相机、编辑器、生成器和分享页应在上述阶段中渐进改造，不重复重写。
